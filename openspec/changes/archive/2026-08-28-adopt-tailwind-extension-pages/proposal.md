## Why

OmniPilot's three extension pages (popup, options, sidepanel) carry ~1,150 lines of hand-written CSS embedded in `<style>` blocks inside their HTML files — 790 lines in `src/options/index.html` alone. Every new UI element requires inventing a class name and hand-authoring layout rules, and the same flex/grid/spacing patterns are re-declared dozens of times across the three surfaces. Adopting a utility-first CSS framework removes that duplication and makes UI work declarative, without changing a single line of functional JavaScript.

This is the lowest-risk step of a three-tier UI modernization. It must land first because Tier 2 (Preact on popup + sidepanel) and Tier 3 (a full framework migration) both assume a working build-time CSS pipeline already exists.

## What Changes

- Add Tailwind CSS v4 as a **build-time-only** devDependency. It compiles to a static stylesheet; no runtime library, no CDN, no JIT in the browser.
- Extend `build.mjs` with a CSS compilation step that emits `dist/tailwind.css`, scanning only `src/popup/`, `src/options/`, and `src/sidepanel/`.
- Configure Tailwind defensively, via v4's CSS-first configuration in `src/styles/tailwind.css`:
  - `prefix(op)` so every utility is namespaced (authored `op:flex`, compiled `.op\:flex`) and every theme variable becomes `--op-*`.
  - Preflight (Tailwind's global CSS reset) **never imported** — only the `theme` and `utilities` layers are pulled in. The existing per-page `*, *::before, *::after` resets stay authoritative.
  - The `--radius-*` theme namespace cleared with `--radius-*: initial` and redefined entirely as `0`, keeping the square-corner product decision mechanically enforced.
  - Color, spacing, font, and shadow scales mapped onto the existing `--appearance-*` tokens, so all 3 themes x 5 visual styles keep working with zero token changes.
- Link `dist/tailwind.css` from the three extension page HTML files, ahead of their existing `<style>` blocks so hand-written CSS still wins on specificity ties.
- Migrate a representative slice of markup — the popup page — from bespoke classes to `op-` utilities, proving the pipeline end-to-end. Options and sidepanel markup are converted incrementally in later changes.
- Add a unit test asserting the Tailwind build output exists, is prefixed, contains no preflight reset, and contains no nonzero `border-radius`.

**No BREAKING changes.** No JavaScript behavior, message passing, storage schema, or provider logic is touched.

## Non-goals

Deliberately left untouched by this change:

- **The content script** (`src/content-script/index.mjs`, `src/content-script/styles.css`). It injects into every website with no Shadow DOM; Tailwind must never reach it. `dist/styles.css` keeps its current hand-written contents.
- **The background service worker** (`src/background/`). It has no UI.
- **All functional JavaScript.** `src/popup/index.mjs`, `src/options/index.mjs`, and `src/sidepanel/index.mjs` are modified only where a DOM element's `class` attribute is set — never their logic, listeners, or storage calls.
- **`src/styles/appearance.css`.** The token contract is consumed, not rewritten.
- **The concatenation build for JavaScript.** No bundler is introduced.
- **Element IDs.** Every `getElementById` target keeps its current ID, so existing unit tests and Playwright selectors keep resolving.

## Hard-constraint compliance

| # | Constraint | How this change complies |
|---|---|---|
| 1 | No IIFE / module-scoped JS output | Not touched. Tailwind emits CSS only; `build.mjs`'s JavaScript concatenation path is unchanged, so `vm.runInContext` unit tests keep seeing top-level declarations. |
| 2 | Content script has no Shadow DOM | Tailwind's content scan is explicitly scoped to `src/popup`, `src/options`, `src/sidepanel`. The content script is excluded and `dist/styles.css` is generated by the existing path. A test asserts `dist/styles.css` contains no `op-` utilities. |
| 3 | MV3 CSP — no CDN, no eval, no runtime JIT | Tailwind runs in Node during `npm run build` and ships a static `dist/tailwind.css` inside the package. No network fetch, no `eval`, no browser-side compiler. |
| 4 | Square corners enforced | The `--radius-*` theme namespace is cleared and redefined as all-zero, and a new test asserts the compiled output contains no nonzero radius. `square-corners.test.js` continues to pass unmodified. |
| 5 | Version sync / permissions / pack entries | `manifest.json`, `package.json`, and `package-lock.json` versions stay in lockstep; only `devDependencies` gains entries. No new permission. `pack.mjs` ENTRIES stay `['manifest.json', 'PRIVACY.md', 'icons', 'dist']` — the new CSS lands inside `dist/`, already packaged. |
| 6 | Functional logic frozen | Only `class` attribute values change. No control flow, no message handlers, no provider routing. |

## Capabilities

### New Capabilities

- `extension-page-styling`: How the popup, options, and sidepanel pages are styled — the build-time utility CSS pipeline, its namespacing and reset policy, its binding to the `--appearance-*` design tokens, and the surfaces it is forbidden from reaching.

### Modified Capabilities

None. No existing spec files exist yet in `openspec/specs/`, and no current requirement changes.

## Impact

**Code**
- `build.mjs` — new CSS compilation step; existing JS and CSS copy steps unchanged.
- `src/popup/index.html` — new `<link>`; markup migrated to `op-` utilities.
- `src/options/index.html`, `src/sidepanel/index.html` — new `<link>` only.
- `src/styles/tailwind.css` (new) — Tailwind v4 CSS-first entry: layer imports, `prefix(op)`, `@source` scoping, and the `@theme` token bridge.

**Dependencies**
- `tailwindcss@4` and `@tailwindcss/cli@4` added to `devDependencies`. Runtime dependency count stays zero.

**Tests**
- `tests/unit/tailwind-build.test.js` (new) — asserts output exists, is prefixed, has no preflight, has no nonzero radius, and has not leaked into `dist/styles.css`.
- `tests/unit/popup.test.js` — unaffected; it asserts on element IDs and text content, not class names.
- `package.json` `test:unit` script gains the new test file.

**Risk**
- Low. The change is additive; if `dist/tailwind.css` were empty the pages would still render from their existing `<style>` blocks.
